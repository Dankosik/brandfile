## Who this is and summary

### Takeaway
One main author, linked to the agency Column Five Media judging by npm and the landing page footer, wrote a deterministic pipeline without an LLM in 7.5 months: extraction, compilation, linter. The best ideas: a rendered check of computed styles, and an approval state tied to a fingerprint. The main weakness: every check is called at the agent's choice, the default profile has no text rules, and the checks do not parse code in TSX/Tailwind.

## Extraction: site, PDF, Figma

### Takeaway
There is not a single LLM call on the server: only CSS parsing, computed styles, counters, and regular expressions. "Intentional" differs from accidental by variable names, selectors, and blacklists. The render source takes priority over named CSS variables, and the rank of the source matters more than confidence. PDF comes down to a search for `#hex` in the text layer. Figma calls are made by the agent itself through someone else's MCP.

### Inferences
- [inference] In auto mode, a low-confidence visual candidate displaces a high web value: `wins` compares source rank before confidence, and a variant requires equal rank. This is derived from the code and was not reproduced at runtime.
- [inference] On the render path, oklch colors are normalized only in the rendered check (through a canvas [render-check.ts#L265](https://github.com/Brandcode-Studio/brandsystem-mcp/blob/eab3927a9eee5c6bada016ccf1c0bf007af696fb/src/lib/render-check.ts#L265)), while the extractor's `rgbToHex` understands only `rgb()` [visual-extractor.ts#L759-L766](https://github.com/Brandcode-Studio/brandsystem-mcp/blob/eab3927a9eee5c6bada016ccf1c0bf007af696fb/src/lib/visual-extractor.ts#L759-L766). ## Voice rules: representation and application

### Takeaway

## Compliance: what is checked, scoring, errors, place in the agent's loop

### Takeaway

The best of them, the render mode of `brand_preflight`, looks at what is actually rendered, but checks only color, font, contrast, and logo. All are called at the agent's choice. If the agent does not call them, nothing happens, and the fact of a call is recorded nowhere.

### Inferences
- [inference] The same content can get four different verdicts. The agent cannot tell which is the main one, and the tool descriptions separate them by hand through "NOT for…". For the user this looks like noise, not like a gate.

## Why there are few users despite broad functionality

### Takeaway
[inference] The breadth is in the tool catalog, but not on the first-run path. The advertised part is either unavailable in the default profile or passes idle, and the differentiator "enforcement" does not work on the code that agents actually write. Part of the reason is simply the age of the project and its distribution.

### Inferences
All items are [inference], based on the facts above. There is no direct data on churn.
1. **The first experience is broken for the main promise.** The slogan is about existing guidelines, but PDF and Figma in core require a restart, and voice and anti-patterns require the interview from full. After auto by URL, the text `brand_check` always passes. The user quickly sees "passed" with no benefit, or runs into the restart.
2. **The PDF extractor is below expectations.** A typical guideline with CMYK, Pantone, and tables will give little. Do and Don't are not saved. This hits exactly the segment the slogan is aimed at.
3. **Enforcement is optional and does not see modern frontend.** No hooks, no CI command, no parsing of TSX and Tailwind. It is easier for a developer to install CSS variables and a rule in AGENTS.md, which can be done without MCP too.
4. **The audiences do not match.** A brand manager does not set up a stdio MCP with Node ≥22.13 [package.json#L28-L29](https://github.com/Brandcode-Studio/brandsystem-mcp/blob/eab3927a9eee5c6bada016ccf1c0bf007af696fb/package.json#L28-L29) and a local Chrome, and a developer does not need personas, journey, and a message matrix. The tool is built for an agency, not for a solo developer.
5. **No external evidence and no community.** One main author, who files the tickets himself, no independent reviews, the project's own metrics at 33–40%, while the marketing promises a result on the first try. A reader who gets to RESULTS.md will see the discrepancy.
6. **The server adds no new capabilities in judgment for the agent.** Without an LLM it comes down to heuristics that the agent can reproduce itself through Read, WebFetch, and a script. The real added value (rendered check, approval, security) is not visible on the storefront.
7. **The commercial center of gravity is elsewhere.** Hosted is closed, and the effort of recent releases went into security and preparing the hosted launch (signed packages, egress proxy, SBOM) [CHANGELOG.md#L5-L36](https://github.com/Brandcode-Studio/brandsystem-mcp/blob/eab3927a9eee5c6bada016ccf1c0bf007af696fb/CHANGELOG.md#L5-L36), not into extraction quality.
8. **Age and category noise.** The project is 7.5 months old. After an average of about 2.3k downloads a month, the last month gave 1,162, but these numbers are noisy because of release spikes and mirrors. 15 stars prove little on their own.

## What to avoid

All items of this section are [inference] from the findings above.

- **Enforcement only through text requests to the agent.** We need hooks, a CI command, or an output check that cannot be skipped.
- **Several checking engines with different palettes and metrics.** We need one engine and one verdict.
- **A pass at zero rules and an `OK` status for rules that cannot be checked.** We need a separate `not_verified` status.
- **Substring search without word boundaries and ASCII `\b`.** Russian text breaks silently. We need Unicode tokenization (`\p{L}`) and lemmatization.
- **Source rank above confidence** and two different priority tables [confidence.ts#L6-L14](https://github.com/Brandcode-Studio/brandsystem-mcp/blob/eab3927a9eee5c6bada016ccf1c0bf007af696fb/src/lib/confidence.ts#L6-L14).
- **Regular expressions as the basis of PDF parsing.** A guideline has to be read by vision or by an LLM with structured output and a page citation. Here this is the main gap.
- **The author's own brand words in shared code** (`orange` → primary) [brand-extract-figma.ts#L280](https://github.com/Brandcode-Studio/brandsystem-mcp/blob/eab3927a9eee5c6bada016ccf1c0bf007af696fb/src/tools/brand-extract-figma.ts#L280).
- **Naming a standard without conformance:** DTCG and DESIGN.md should be checked with a validator in CI.
- **Hiding tools that the responses refer to.** The small profile must itself carry the whole promised scenario.
- **Promises of on-brand on the first try** when the project's own measurements are 33–40%.
- **Fitting descriptions to a public dev set as proof of routing quality** [RESULTS.md#L7-L13](https://github.com/Brandcode-Studio/brandsystem-mcp/blob/eab3927a9eee5c6bada016ccf1c0bf007af696fb/eval/RESULTS.md#L7-L13).
- **Breadth for breadth's sake:** 44 tools, personas, and matrices with a weak core. Dependencies on closed services (Clearbit) also need control.

## Open questions

- What is the real extraction accuracy on 20–30 real brands with known ground truth? The project has no correctness metric, but its corpus and script can be used as a template.
- Will live sites confirm that a named CSS variable is displaced by the first chromatic button background, and the gap with oklch? This is derived from the code and was not reproduced.
- How much does `tools/list` actually take in core and full once JSON Schema is counted? It needs to be measured when run in a sandbox.
- Would a mandatory hook (a rendered check on Stop or PostToolUse) raise task completion compared with a text request? There is a ready anti-result for `output_contract`, but no data on a mandatory gate.
- What is the effect of brand context compared with no context at all and with a plain AGENTS.md file? The project has no control arm.
- How does a Studio package turn into a local runtime, and does a pull give voice rules in core? I did not trace this path to the end.
- What terms and prices will the hosted `@brandcode/mcp` have after launch? There is no public data.
